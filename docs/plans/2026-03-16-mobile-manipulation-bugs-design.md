# 모바일 조작 버그 수정 설계

## 요약

모바일 편집기에서 이미지, 텍스트, 스티커의 조작 상태가 서로 다른 기준으로 관리되고 있어 선택 상태와 실제 Konva 노드 변형 결과가 어긋난다. 이번 수정은 `App`의 선택 상태를 `CanvasStage`에 일관되게 전달하고, 텍스트/스티커 변형이 끝날 때 실제 표시 크기를 상태에 안전하게 반영하도록 정리하는 데 초점을 둔다.

## 접근 옵션

### 옵션 1. 최소 버그 수정
- 이미지 선택 전달, 텍스트/스티커 `onTransformEnd` 계산식만 고친다.
- 장점: 변경 범위가 작다.
- 단점: 모바일 터치 시작 타이밍 문제와 스티커 실시간 조작 불안정이 남을 수 있다.

### 옵션 2. 권장안
- `CanvasStage`가 항상 `editorState.selection`을 기준으로 선택을 해석하게 한다.
- 이미지 업로드 직후와 모바일 터치 시작 시 선택을 즉시 동기화한다.
- 텍스트/스티커는 transform 종료 시 스케일을 상태에 반영한 뒤 Konva 노드 스케일을 `1`로 되돌려 다음 조작 기준을 안정화한다.
- 장점: 현재 증상 3가지를 한 번에 설명하는 공통 원인을 같이 정리할 수 있다.
- 단점: 테스트와 렌더 로직을 함께 건드려야 한다.

### 옵션 3. 구조 리팩터링
- `CanvasStage` 내부의 인라인 노드 컴포넌트를 분리하고 스티커 이미지 로딩 상태도 상위에서 관리한다.
- 장점: 장기적으로 가장 안정적이다.
- 단점: 이번 버그 수정 범위를 넘어가고 회귀 위험이 커진다.

## 선택한 방향

옵션 2를 적용한다. 사용자 요구는 “모바일에서 바로 조작 가능해야 한다”는 동작 안정성이라서, 선택 상태와 transform 저장 기준을 바로잡는 것이 가장 짧고 안전하다.

## 테스트 전략

- 소스 기반 회귀 테스트로 `App`이 `editorState.selection`을 `CanvasStage`에 넘기는지 확인한다.
- 모바일 이미지 터치 시작이 선택 동기화와 핀치 시작을 함께 처리하는지 확인한다.
- 텍스트와 스티커 transform 종료 시 실제 크기 반영 후 노드 스케일을 초기화하는 코드를 검증한다.
