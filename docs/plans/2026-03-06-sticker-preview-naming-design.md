# Sticker Preview Naming Design

**Date:** 2026-03-06

**Summary:** 오른쪽 사이드바의 스티커 UI에서 중분류 카드 미리보기와 상세 스티커 미리보기의 파일명 규칙을 분리한다. 중분류 카드는 `1s~10s`, 상세 스티커는 `1ss~10ss` 규칙을 사용해 역할을 명확히 나눈다.

## Context

- 현재 스티커 카탈로그는 중분류 카드 미리보기와 상세 스티커 슬롯이 같은 `1s~10s` 자산을 함께 사용한다.
- 사용자는 두 레이어의 이미지를 구분해서 관리하고 싶어 한다.
- 현재 카테고리는 `기본 스티커`, `꾸미기 스티커` 두 개뿐이며, 각각 `1s`, `2s`를 미리보기로 사용하면 충분하다.

## Decision

1. 중분류 카드 미리보기는 `public/stickers/1s.*`, `public/stickers/2s.*`를 사용한다.
2. 카테고리 내부의 상세 스티커 슬롯은 `public/stickers/1ss.*`부터 `public/stickers/10ss.*`까지를 사용한다.
3. 확장자 자동 탐색 순서는 기존과 동일하게 `.svg`, `.png`, `.webp`, `.jpg`, `.jpeg`를 유지한다.
4. 현재 존재하는 두 카테고리만 카드 미리보기 파일을 직접 지정하고, 나머지 `3s~10s` 규칙은 향후 카테고리 확장 시 그대로 재사용한다.

## Why This Approach

- 카드 이미지와 실제 삽입 스티커 이미지의 역할이 분리되어 자산 관리가 쉬워진다.
- 현재 UI 구조를 크게 바꾸지 않고 파일명 규칙만 정리할 수 있다.
- 앞으로 카테고리가 추가되어도 같은 규칙을 재사용할 수 있다.

## Affected Areas

- `src/ui/stickerCatalog.ts`
- `tests/ui/stickerCatalog.test.ts`
- 필요 시 스티커 관련 렌더링 컴포넌트에서 새 슬롯 키 규칙을 그대로 읽는지 확인

## Verification

- 카탈로그 테스트에서 카드용/상세용 경로 생성 규칙을 검증한다.
- `npm run build`
- `npm run lint`

## Notes

- 현재 작업 트리에 사용자 변경 사항이 있으므로, 관련 파일은 기존 변경을 덮어쓰지 않도록 최소 범위만 수정한다.
- 문서만 추가하며 커밋은 별도 요청이 있을 때 진행한다.
