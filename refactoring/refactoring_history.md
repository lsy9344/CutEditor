# CutEditor 스티커 기능 추가 및 UI/UX 리팩토링 상세 내역 및 작업지시서

본 문서는 CutEditor 애플리케이션에 '스티커' 기능을 추가하고 편집 편의성을 높이기 위해 진행된 UI/UX 개편 및 리팩토링 작업의 상세 기록이자, 향후 유사 기능 개발 시 참고할 수 있는 **상세 설계 및 작업지시서(Work Directive)**입니다.

---

## 1. 개요 및 기획 (Planning)

*   **목표:** 캔버스에 불러온 이미지에 스티커 및 텍스트를 직관적으로 추가・편집할 수 있는 기능 구현.
*   **방향성:** 기존의 Neo-Brutalism 디자인 시스템을 계승하되, 화면의 인지적 과부하(Cognitive Overload)를 방지하기 위해 탭 뎁스 모델과 상황 인지형(Context-Aware) 인터페이스를 도입.
*   **주요 대상 파일:**
    *   사이드바 및 UI: `src/ui/SidebarLeft.tsx`, `src/ui/SidebarRight.tsx`
    *   디자인 시스템: `src/components/components.css`
    *   메인 캔버스: `src/canvas/CanvasStage.tsx`
    *   상태 관리: `src/App.tsx`, `src/types/frame.ts`

## 2. UI/UX 및 디자인 시스템 세부 명세 (Design Guidelines)
> 개발 시 반드시 준수해야 하는 시각적/경험적 규칙 모음입니다.

### 2.1. 시각적 아이덴티티 (Neo-Brutalism)
본 시스템은 가독성이 높고 직관적인 **Neo-Brutalism (네오 브루탈리즘)** 스타일을 엄격히 적용합니다.
*   **선과 그림자(Borders & Shadows):** 모든 컨테이너와 버튼은 두꺼운 테두리(`3px solid #000`)를 가지며, 플랫한 하드 쉐도우(`4px 4px 0px 0px #000`)를 적용해 깊이감을 주어 누를 수 있는 요소임을 명확히 합니다.
*   **마이크로 인터랙션(Micro-interactions):**
    *   **Hover 상태:** 마우스 오버 시 `translate(-2px, -2px)`로 요소가 떠오르며 그림자가 확장(`6px 6px`)됩니다.
    *   **Active 상태:** 클릭/터치 시 `translate(2px, 2px)`로 요소가 눌리는 물리적 피드백을 제공하고 그림자가 축소(`0px 0px`)되어야 합니다.
    *   **애니메이션:** `linear-fade-in` 클래스를 통한 0.3s ease-out 페이드 + 슬라이드인(`translateY(4px) → 0`) 전이. 모든 메뉴 전환, 카드 등장에 적용.
    *   **전환 속도:** `.linear-transition`(0.2s), `.linear-transition-fast`(0.1s) 유틸리티 클래스로 일관된 모션 속도 관리.
*   **타이포그래피:** `Space Grotesk` 폰트를 중심으로 두꺼운 폰트 웨이트(Bold/ExtraBold 800~900)를 제목(`h1~h4`)에 사용하여 시각적 위계를 뚜렷하게 잡습니다.
*   **컬러 시스템:**
    *   Primary: `#E3D5CA` (Beige) — 브랜드 핵심 색상
    *   Background: `#F5EBE6` (Main), `#FFF9F5` (Sub), `#FFFFFF` (Card)
    *   Border / Text: `#000000` — 브루탈리즘 핵심 요소
    *   Accent: Success `#52B788`, Warning `#FFB703`, Error `#E63946`
*   **Border Radius:** 모든 요소에 `0px` (완전 직각) — 브루탈리즘 핵심 원칙
*   **스크롤바 스타일링:** WebKit 커스텀 스크롤바(12px, 베이지 thumb, 검정 border)로 디자인 일관성 유지

### 2.2. CSS 변수 세부 명세 (Design Tokens)
> `components.css`의 `:root`에 정의된 토큰들의 사용 규칙입니다.

| 토큰 | 값 | 사용 용도 |
|---|---|---|
| `--shadow-sm` | `2px 2px 0 0 #000` | 작은 요소 (뱃지, 인풋) |
| `--shadow-base` | `4px 4px 0 0 #000` | 기본 요소 (카드, 호버) |
| `--shadow-hover` | `6px 6px 0 0 #000` | 호버 시 확장 그림자 |
| `--shadow-active` | `0px 0px 0 0 #000` | 클릭/터치 시 눌림 효과 |
| `--shadow-lg` | `8px 8px 0 0 #000` | 대형 요소 (모달) |
| `--border-width` | `3px` | 전역 테두리 두께 |
| `--linear-backdrop` | `rgba(245,235,230,0.8)` | 모달 배경 오버레이 |

### 2.3. 모바일 특화 UX (Mobile-First Experience)
데스크탑과 모바일 간 상이한 입력 방식(Mouse vs Touch)을 고려하여 분기 처리합니다 (`isMobile` 감지).

*   **반응형 레이아웃 (Responsive Breakpoints):**
    *   `> 1200px`: 3컬럼 그리드 `320px / 1fr / 320px` (Full Desktop)
    *   `1024px ~ 1200px`: 3컬럼 그리드 `300px / 1fr / 300px`
    *   `768px ~ 1024px`: 3컬럼 그리드 `280px / 1fr / 280px`
    *   `< 768px`: 1컬럼 수직 스택 `1fr` (모바일 풀스크린)
*   **미리보기(Popover) 제스처:** 타겟 터치가 어려운 모바일을 고려해 `Hover` 기반의 팝오버 작동은 비활성화합니다. 대신 터치 즉시 선택 로직을 실행하되 사용자가 방금 누른 것이 무엇인지 알 수 있도록 **1초간(1000ms) 유지되는 툴팁/미리보기**를 제공합니다.
*   **커스텀 공유 인터페이스 (Native Feel):** 모바일 내보내기 시 파일 시스템 다이얼로그(`showSaveFilePicker`) 대신, 네이티브 앱 경험을 위해 하단 바텀 시트/모달 느낌의 **오버레이**를 띄우고, `Web Share API`를 통한 네이티브 '사진에 저장' 및 외부 앱 공유기능을 우선 제공합니다.
*   **입력창 최적화:** 모바일 온스크린 키보드가 올라올 때 레이아웃이 깨지지 않도록, 설정 패널이나 입력창은 Scroll-View(`overflow-y: auto`) 구조를 유지해야 합니다.
*   **핀치 줌:** 이미지 슬롯 위에서 두 손가락 핀치 줌 지원 (`TouchEvent.touches.length >= 2` 감지 → `initDistance` 대비 `scaleBy` 계산).
*   **모바일 내보내기 해상도:** 메모리 한계 고려하여 `pixelRatio`를 최대 3배로 제한 (Desktop은 1200 DPI 기준 원래 비율 적용).

### 2.4. 접근성 및 키보드 네비게이션 (Accessibility - A11y)
*   **포커스 링 (Focus Ring):** 키보드 탭 네비게이션 시 사용자의 현재 위치를 명확히 알 수 있도록 `:focus-visible` 속성에 두꺼운 아웃라인(`3px solid #E63946`, offset `2px`) 적용.
*   **Aria 속성:** 시각 장애인 및 스크린 리더 사용자를 배려하여, 아이콘만 있는 버튼(예: 텍스트 정렬, 닫기 버튼)에 반드시 `aria-label`을 부여하고, 활성 탭/토글 버튼에는 `aria-pressed`, `aria-selected` 속성을 정확히 업데이트합니다.

### 2.5. 피드백 및 에러 상태 (Feedback & Error States)
*   **토스트 알림 (Toast Notifications):** 사진 저장 성공, 이미지 로드 실패, 용량 초과 등의 상황에서 화면 상/하단에 짧게 등장하는 브루탈리즘 스타일의 토스트 다이얼로그 도입 (성공/경고/에러 명확한 컬러 구분).
*   **빈 상태 (Empty States):** 초기화면 또는 검색/필터 결과가 없을 때 당황하지 않도록, 유쾌하고 직관적인 아이콘이나 굵은 타이포그래피 안내 문구("프레임을 먼저 골라주세요!") 노출.

## 3. 작업지시서 (기능 및 컴포넌트 명세서)

### 3.1. 좌측 사이드바 (프레임 선택 영역) — ★ 전면 개편 필요

> **핵심 문제점:** 현재 좌측 사이드바의 2Depth 프레임 선택이 **텍스트 라벨**(예: '2컷 가로', '2컷 세로')만으로 구성되어 있어, 실제 프레임 레이아웃의 시각적 차이를 손님이 직관적으로 파악할 수 없습니다. 미리보기 이미지(`/popover/*.png`)는 데스크탑 onMouseEnter 팝오버로만 제공되며, 모바일에서는 1초 툴팁에 불과합니다.

#### 3.1.1. 현재 구조 (As-Is)
```
좌측 사이드바 (320px 고정폭)
├─ 헤더: "다비스튜디오 컷편집기"
├─ 1Depth: [1컷] [2컷] [4컷] [6컷] [9컷]  ← 5개 카테고리 버튼 (5컬럼 그리드)
└─ 2Depth: 선택된 카테고리의 프레임 버튼들
   ├─ "2컷 가로" ← 텍스트만, 호버 시 팝오버 이미지(300px 너비)
   └─ "2컷 세로" ← 텍스트만, 호버 시 팝오버 이미지(300px 너비)
```

#### 3.1.2. 개선 목표 (To-Be): **사이드바 + 캔버스 연동 '프레임 갤러리' 모드**

**핵심 아이디어:** 좌측 사이드바의 공간적 한계(320px 폭)를 인정하고, 센터 캔버스 영역을 **프레임 미리보기 갤러리**로 활용합니다. 프레임이 아직 선택되지 않았거나, 카테고리 버튼을 눌렀을 때 캔버스에 해당 카테고리의 프레임 미리보기 이미지들을 카드 형태로 보여줍니다.

```
[개선된 UX 플로우]

1. 초기 상태 (프레임 미선택)
   ├─ 좌측: n컷 카테고리 버튼만 표시
   └─ 캔버스: 온보딩 빈 상태(Empty State) 디자인 노출 ("왼쪽에서 원하는 컷 수를 먼저 선택해 주세요!" 메시지를 브루탈리즘 타이포그래피/일러스트와 함께 배치)

2. 카테고리 선택 (예: '2컷' 클릭)
   ├─ 좌측: '2컷' 활성 표시, 하위 프레임 리스트 (간략 텍스트 + 아이콘)
   └─ 캔버스: '2컷' 카테고리의 모든 프레임 미리보기 카드 렌더링
      ┌─────────────────────────────────────┐
      │  [1번 프레임: 2컷 가로]   [2번 프레임: 2컷 세로]  │
      │  ┌──────────────┐      ┌──────────────┐  │
      │  │              │      │              │  │
      │  │  미리보기 img  │      │  미리보기 img  │  │
      │  │  (가로 레이아웃) │      │  (세로 레이아웃) │  │
      │  │              │      │              │  │
      │  └──────────────┘      └──────────────┘  │
      │     "2컷 가로"              "2컷 세로"       │
      │    클릭하여 선택            클릭하여 선택      │
      └─────────────────────────────────────┘

3. 프레임 카드 클릭 → 편집 모드 전환
   ├─ 좌측: 선택된 프레임 강조, 다른 프레임으로 전환 가능
   └─ 캔버스: 기존 Konva 편집 캔버스 모드로 전환 (현재 구현과 동일) + 각 슬롯에 "여기를 눌러 사진을 추가하세요" 시각적 힌트 제공
```

#### 3.1.3. 프레임 갤러리 캔버스 상세 명세

##### 캔버스 모드 상태 관리
`App.tsx`에 새로운 상태를 도입합니다:
```typescript
type CanvasMode = 'gallery' | 'editor';  // 캔버스의 현재 모드

// 상태 관리
const [canvasMode, setCanvasMode] = useState<CanvasMode>('gallery');
```

*   **`gallery` 모드:** 프레임 미선택 상태 또는 카테고리만 선택한 상태. 캔버스에 미리보기 카드를 렌더링.
*   **`editor` 모드:** 특정 프레임이 선택된 상태. 기존 Konva 편집 캔버스를 렌더링.

##### 갤러리 카드 레이아웃 규칙

| 카테고리 | 하위 프레임 수 | 카드 그리드 | 비고 |
|----------|--------------|-----------|------|
| 1컷 | 2개 (레터링, 프레임) | 1 × 2 | 세로 프레임만 |
| 2컷 | 2개 (가로, 세로) | 1 × 2 | 가로/세로 혼합 ★ |
| 4컷 | 1개 (세로) | 1 × 1 | 즉시 편집모드 진입 가능 |
| 6컷 | 1개 (세로) | 1 × 1 | 즉시 편집모드 진입 가능 |
| 9컷 | 1개 (세로) | 1 × 1 | 즉시 편집모드 진입 가능 |

> **주의 (하위 프레임이 1개인 경우):** 4컷/6컷/9컷처럼 프레임 옵션이 1개뿐인 카테고리는 갤러리를 거치지 않고 **바로 편집 모드로 전환**하는 것을 검토합니다 (사용자 클릭 한 번 절약). 단, 향후 가로 프레임이 추가될 수 있으므로 갤러리 화면 자체는 유지하되 `autoSelect` 옵션으로 분기 처리합니다.

#### 3.1.4. ★ 가로 프레임의 캔버스 배치 전략

> **물리적 제약:** 캔버스는 4×6인치(10×15cm) 실제 인화지를 모델링합니다.
> - **세로(VERTICAL):** 483 × 719 px — 캔버스 영역에 자연스럽게 적합
> - **가로(HORIZONTAL):** 719 × 483 px — 센터 영역 폭에 비해 넓고 높이가 짧아 여백이 많이 남음

##### 가로 프레임 배치 문제와 해결 전략

| 문제 | 현재 상태 | 개선 방안 |
|------|----------|---------|
| 가로 프레임 편집 시 캔버스 위아래 여백 과다 | `wrapperTargetHeight` 계산으로 높이 조정 시도 중 | Auto-Fit 알고리즘이 `Math.min(ratioX, ratioY)` 기반으로 자동 대응하므로, 센터 영역의 높이 축소에 맞춰 줌 배율이 자동 조정됨. 추가 개선 불필요하나, 갤러리 모드에서 가로 프레임 카드는 가로로 길게 배치해야 함 |
| 갤러리에서 가로/세로 카드 크기 불일치 | N/A (갤러리 미구현) | 갤러리 그리드에서 가로 프레임 카드는 `grid-column: span 2` 또는 별도 섹션으로 배치. 미리보기 이미지 비율은 `aspect-ratio: 719/483`(가로) vs `aspect-ratio: 483/719`(세로)로 자동 대응 |
| 가로↔세로 전환 시 캔버스 리사이즈 지연 | `ResizeObserver` + `applyAutoFit` | 편집모드 진입 시 `requestAnimationFrame`으로 초기 핏 1회 강제 실행 |

##### Auto-Fit 알고리즘 (기존 구현 보존)
```
공식: zoom = Math.min(containerWidth / stageWidth, (containerHeight - paddingY) / stageHeight)
제한: 0.1 ≤ zoom ≤ 1.0
트리거: ResizeObserver 또는 window.resize
paddingY = 40px (상하 여유)
```

type FrameOption = {

##### 좌측 사이드바 UI 변경 사항
1.  **1Depth (카테고리 버튼):** 기존 5컬럼 그리드 유지. 단, 선택 시 `canvasMode = 'gallery'`로 전환.
2.  **2Depth (프레임 리스트):** 텍스트 + 소형 아이콘(세로/가로 방향 표시) 구성. 사이드바에서는 미리보기 이미지를 **올리지 않음** (캔버스 갤러리에 위임).
3.  **'편집 중' 상태 표시:** 프레임 선택 후 편집 모드 진입 시, 선택된 프레임명 옆에 `✏️ 편집 중` 뱃지 표시.
4.  **'다른 프레임 보기' 버튼:** 편집 모드에서 갤러리 모드로 돌아가는 버튼 제공. 기존 편집 내용(텍스트, 스티커)은 프레임 전환 시 **초기화됨을 사전 경고** (confirm 다이얼로그).

### 3.2. 우측 사이드바 (편집 도구 영역)
**목표:** Context-Aware 기반의 도구 제공으로 편집 흐름 단순화.
*   **상황 인지형 탭(Tab) 네비게이션:**
    *   캔버스에서 아무것도 선택하지 않았을 때는 '글씨' 탭 노출.
    *   캔버스에서 **텍스트 객체 클릭 시** -> 자동으로 '글씨' 탭으로 전환.
    *   캔버스에서 **스티커 객체 클릭 시** -> 자동으로 '스티커' 탭으로 전환.
*   **글씨 편집 도구 세부 요구사항:**
    *   텍스트 입력은 `textarea` 폼을 사용하며, 추천 문구(`select` dropdown)에서 문장 선택 시 입력창에 값이 즉각 대체되도록 구현합니다.
    *   UI 위계를 고려해 '폰트 선택' 기능은 버튼 형태로 노출하되, 리스트 길이 대응을 위해 **모달 다이얼로그 방식**으로 열리게 합니다. (Z-Index: 1000 배경 Backdrop 적용 필수, ESC 키보드 조작 이스케이프 지원)
    *   **폰트 미리보기:** 각 폰트 항목에 고정 미리보기 텍스트(`내 세상은 네가 있어 더 아름다워♥, 2025.09.13`)를 해당 폰트로 렌더링하여 시각적 선택 지원.
    *   **텍스트 정렬:** 좌/중앙/우 정렬 버튼 (SVG 아이콘). 선택된 텍스트가 없으면 비활성화 (`opacity: 0.5`, `cursor: not-allowed`).
    *   **프레임별 기본 텍스트 위치:** 프레임 타입에 따라 텍스트 삽입 기본 좌표가 다름 (예: `1l` → 중앙 상단 `(241.5, 100)`, `2h` → 우측 `(620, 241.5)`).
*   **스티커 편집 도구 세부 요구사항:**
    *   도입된 스티커 에셋 리스트(`/stickers/*.svg`) 항목들을 3단 그리드로 배치하여 한눈에 파악하도록 합니다. 썸네일은 컨테이너를 벗어나지 않게 `object-fit: contain` 을 적용.
    *   **성능 최적화:** 스티커 수가 많아질 경우 렌더링 지연을 겪지 않도록 가상화(Virtualization) 스크롤 또는 이미지 지연 로딩(`loading="lazy"`) 기법을 도입하여 DOM 렌더링 부하를 줄입니다.
*   **고정 액션 (저장/내보내기):**
    *   어떤 탭을 보고 있더라도, 사용자가 즉시 작업물을 저장할 수 있도록 우측 사이드바 하단 혹은 최상단에 **"편집된 사진 저장" (Save Edited Photo)** 브랜드 컬러 버튼을 부동(Fixed) 여백 혹은 최우선 위계로 고정 노출합니다.

### 3.3. 캔버스 및 전역 상태 관리
**목표:** 반응형 레이아웃 붕괴 방지 및 직관적인 다중 오브젝트 제어 환경 구축.

#### 3.3.1. 캔버스 모드 전환 (★ 신규)
캔버스 컴포넌트(`CanvasStage.tsx`)는 두 가지 모드를 지원합니다:

*   **갤러리 모드 (Gallery Mode):**
    *   프레임이 선택되지 않았거나, 카테고리만 선택된 상태
    *   Konva Stage를 렌더링하지 않고, 순수 React DOM으로 미리보기 카드 그리드 렌더링
    *   카드 클릭 시 `onFrameSelect` → 에디터 모드로 전환
    *   배경색: `var(--linear-neutral-700)` (서브 배경)
    *   카드 진입 애니메이션: `linear-fade-in` 클래스 적용

*   **에디터 모드 (Editor Mode):**
    *   특정 프레임이 선택된 상태 (기존 동작 100% 유지)
    *   `react-konva`의 `Stage > Layer` 구조로 프레임 이미지, 슬롯, 유저 이미지 렌더링
    *   색상 치환, 이미지 드래그/줌, 텍스트/스티커 편집 모든 기능 보존

#### 3.3.2. 뷰포트 최적화 Auto-Fit 알고리즘
*   모든 스크린(태블릿, 모바일)에서 캔버스에 스크롤바가 생기지 않고 100% 핏 되도록 줌 배율을 정밀하게 제어합니다.
*   **공식:** `Math.min(containerWidth / stageWidth, containerHeight / stageHeight)`

#### 3.3.3. 오브젝트 선택(Selection)의 배타성
*   `App.tsx`의 루트 상태에서 `selectedTextId`, `selectedStickerId` 중 하나만 활성화 상태를 갖도록 분기 처리 로직 구비.

#### 3.3.4. 조작 제어기(Transformer) 부착 및 고급 제스처
*   선택된 스티커 및 텍스트에는 `react-konva`의 `Transformer`를 붙여 회전 및 스케일 조정 액션을 지원하며, 스티커는 축소 시 보이지 않게 되는 문제를 막기 위해 `boundBoxFunc`로 최소 사이즈 10px X 10px 리미트를 겁니다.
*   **모바일 복합 제스처 지원:** 터치 디바이스에서 선택된 스티커/텍스트 위 두 손가락 핀치 제스처 시, 스케일(Zoom)과 회전(Rotation)이 이질감 없이 동시에 발생하도록 멀티 터치 제스처 핸들러를 고도화합니다.

#### 3.3.5. 프레임 색상 커스텀 팔레트
*   프리셋 컬러 8종: `#FFFFFF`, `#000000`, `#DCDCDC`, `#fe9fb3`, `#ffe4c4`, `#C8F7DC`, `#C6E2FF`, `#ffc1cc`
*   외부 설정 파일(`/config/frame_palette.json`)로 오버라이드 가능 (최대 24색)
*   HSV 원형 컬러 피커 지원 (캔버스 기반 160px 원형 팔레트)

#### 3.3.6. 내보내기(Export) 명세 관리 (신규 추가)
*   **해상도 한계 방어:** 모바일 사파리 등의 OOM(Out of Memory) 회피를 위해 디바이스 픽셀 비율(`devicePixelRatio`)을 기반으로 내보내기 배율을 동적 계산하되, 상한선을 3x 등으로 제한.
*   **파일명 규칙:** `CutEditor_YYYYMMDD_HHMMSS.png` 등 저장 시점 기반 직관적인 네이밍.
*   **품질 확보:** 사진 출력/인화 목적인 4x6 핏이므로 손실 없는 `image/png` 출력을 기본으로 하되 효율적 용량 최적화 수행.

5.  **프레임 템플릿 확장:** 가로 4컷(`4h`), 가로 6컷(`6h`), 가로 9컷(`9h`) 레이아웃 추가 — 현재 `frame.ts`에 주석으로 슬롯 정의가 준비되어 있으나 미활성 상태.
6.  **갤러리 카드 애니메이션 고도화:** 카드 진입 시 staggered 애니메이션 (순차 등장), 선택 시 스케일업 피드백.
7.  **자동 저장 및 세션 복구 (Auto-save):** 브라우저 로컬 스토리지(`localStorage` / `IndexedDB`)를 활용해 페이지 새로고침이나 실수에 의한 이탈 후 재접속 시 이전 편집 상태(이미지 배치, 스티커 위치, 텍스트 등)를 복구하는 안전망 구축.
8.  **키보드 단축키 (Keyboard Shortcuts):** `Delete`/`Backspace` (객체 삭제), `Ctrl+C / Ctrl+V` (스티커, 텍스트 복제), `Ctrl+Z` (실행 취소) 등 데스크탑 파워 유저를 고려한 편의기능 확장.
9.  **다크 모드 (Dark Mode) 지원 검토:** 네오 브루탈리즘의 강렬한 색감을 반전시킨 다크 테마 시스템(토큰맵) 고안 (예: 배경 `#1A1A1A`, 선 색상 `#FFFFFF`, 네온빛 엑센트 등).

### 7.1. UI/UX 비효율 및 개선 제안

#### ⚠️ 하위 프레임 1개인 카테고리의 갤러리 UX 최적화
- **문제:** 4컷/6컷/9컷은 현재 하위 옵션이 각각 1개뿐(`4v`, `6v`, `9v`). 갤러리 화면에 카드 1장만 보여주는 것은 불필요한 추가 클릭을 유발합니다.
- **전제:** 4컷/6컷/9컷 카테고리에는 **향후 가로 프레임(`4h`, `6h`, `9h`) 등이 추가될 예정**이므로, 갤러리 모드 인프라 자체는 반드시 유지해야 합니다.
- **개선안:** 갤러리 컴포넌트와 카드 렌더링 로직은 모든 카테고리에 동일하게 구현하되, `options.length === 1`일 때는 `autoSelect` 로직으로 **갤러리를 거치지 않고 즉시 편집모드에 진입**하는 단축 경로를 적용. 옵션이 2개 이상이 되는 순간 자동으로 갤러리가 활성화됩니다.

#### ⚠️ 모바일 갤러리 모드 레이아웃 명세 부재
- **문제:** 현재 CSS 반응형은 `< 768px`에서 `grid-template-columns: 1fr` 1컬럼 수직스택으로 전환. 이 상태에서 캔버스 영역이 갤러리 카드 그리드가 됐을 때의 배치/스크롤 동작이 정의되지 않았습니다.
- **개선안:** 모바일 갤러리 모드에서는 사이드바(좌측)와 캔버스(갤러리)가 수직으로 쌓이므로, 갤러리 카드를 **2컬럼 그리드(50%/50%)**로 배치하고 세로 스크롤 허용. 갤러리 영역의 `max-height`를 `60vh`로 제한하여 하단 우측 사이드바가 접근 불가능해지는 문제를 방지.

#### ⚠️ 프레임 전환 시 데이터 초기화 경고 시점 모호
- **문제:** 문서 3.1.5항에서 프레임 전환 시 `confirm` 다이얼로그로 사전 경고를 제안하나, 현재 `handleFrameSelect()`는 이미 **무조건** 텍스트/스티커/이미지를 초기화합니다. 갤러리 모드 도입 후 언제 경고를 띄울지 불명확합니다.
- **개선안:** 경고 시점을 명확히 정의 — "편집모드에서 **다른 카테고리** 또는 **다른 프레임 카드** 선택 시, 기존 편집 데이터(텍스트/스티커/이미지)가 1건 이상 존재하면 `confirm` 표시". 같은 프레임 재선택 시에는 경고 불필요.

#### ⚠️ 1컷 카테고리의 프레임 구분이 직관적이지 않음
- **문제:** 1컷은 "사진에 글씨새기기"(`1l`)과 "1컷 프레임"(`1f`)으로 나뉘는데, 다른 카테고리(2컷/4컷...) 대비 명명 규칙이 다릅니다. "레터링"이라는 단어가 라벨에 없어 사용자가 차이를 이해하기 어렵습니다.
- **개선안:** 갤러리 카드에 미리보기 이미지와 함께 **기능 설명 서브텍스트** 추가 (예: "사진 위에 직접 텍스트를 올려보세요" vs "프레임 안에 사진을 넣어보세요").

### 7.2. 코드 구현 가능성 문제

#### 🚫 `CanvasStage.tsx` 단일 책임 원칙 위반 우려
- **문제:** `CanvasStage.tsx`는 이미 **1,520줄**로 비대합니다. 여기에 갤러리 모드(React DOM 카드 그리드)를 분기 추가하면 가독성과 유지보수성이 급격히 저하됩니다.
- **개선안:** 갤러리 UI를 별도 컴포넌트(`FrameGallery.tsx`)로 분리하고, `CanvasStage.tsx`는 편집모드 전용으로 유지. `App.tsx`에서 `canvasMode` 상태에 따라 조건부 렌더링:
  ```tsx
  {canvasMode === 'gallery' ? <FrameGallery ... /> : <CanvasStage ... />}
  ```

#### 🚫 `FrameType` 호환 별칭 미처리
- **문제:** `frame.ts`에는 `"2"`, `"4"`, `"6"`, `"9"` 호환용 레이아웃이 존재하나, 문서의 갤러리 카테고리 테이블(3.1.3)에서 이를 완전히 무시합니다. `FRAME_OPTIONS_BY_CATEGORY`도 이 별칭을 포함하지 않습니다.
- **개선안:** 호환 별칭의 목적과 처리 방침을 명시. 권장 방안: 이 별칭들은 외부 연동용이므로 UI에서는 노출하지 않고, `FRAME_OPTIONS_BY_CATEGORY`에서도 제외하되, `handleFrameSelect()`에서 별칭 → 정규 타입 매핑(`"4" → "4v"`)을 수행.

#### 🚫 `EditorState` 확장 범위 미정의
- **문제:** `canvasMode` 상태를 `App.tsx`의 로컬 `useState`로 관리할지, `EditorState` (`store.ts`)에 포함할지 결정되지 않았습니다. 현재 `store.ts`는 순수 타입 + 초기값만 제공하고 Zustand 등은 미도입 상태.
- **개선안:** `canvasMode`는 URL/히스토리에 반영할 필요가 없으므로 `App.tsx`의 로컬 `useState`로 관리 확정. `store.ts`의 `EditorState`에는 추가하지 않음.

### 7.3. CSS / 디자인 토큰 불일치

#### 🔧 갤러리 카드 CSS의 변수명 오류
- **문제:** 문서 3.1.3의 갤러리 카드 CSS에서 `border-radius: var(--radius-base)` 사용하나, 실제 `components.css`의 토큰은 `--linear-radius-base`입니다.
- **수정:** `var(--radius-base)` → `var(--linear-radius-base)` (값은 `0px`이므로 네오 브루탈리즘 원칙과 정합).

#### 🔧 `.linear-card` hover 부작용
- **문제:** 현재 `.linear-card:hover`에 `translate(-2px, -2px)` + `shadow-hover`가 전역 적용됨. 좌측 사이드바(`<aside className="linear-card">`)에도 마우스 오버 시 사이드바 전체가 떠오르는 의도치 않은 동작 발생합니다.
- **개선안:** 사이드바에는 `.linear-card--static` 변형 클래스를 적용하여 hover 효과를 비활성화하거나, 사이드바 전용 클래스를 분리.

### 7.4. 에셋 및 데이터 정합성

#### ⚠️ 스티커 에셋 부족 — 가상화 스크롤 시기상조
- **현황:** `/public/stickers/`에 SVG 3개(`face-smile.svg`, `heart.svg`, `star.svg`)만 존재.
- **문제:** 문서 3.2에서 "스티커 수가 많아질 경우 가상화 스크롤"을 제안하나, 현재 에셋으로는 과도한 최적화입니다.
- **개선안:** Phase 1에서는 `loading="lazy"` 적용만 하고, 스티커 에셋 **최소 20개 이상** 확보 후 가상화 도입을 검토. Phase 4 에셋 관리에 스티커 에셋 확충 항목 추가.

#### ⚠️ 갤러리 미리보기 이미지 에셋 부재
- **현황:** `/public/popover/`에 7장의 미리보기 이미지(1f, 1l, 2h, 2v, 4v, 6v, 9v)가 존재하나, 갤러리 카드용 고해상도 이미지(`previewImage` 필드)는 없습니다.
- **개선안:** Phase 4 이전에 별도 갤러리 이미지를 준비하지 않고, **기존 popover 이미지를 갤러리에서 재활용**하는 것을 기본 전략으로 확정. `FrameOption` 타입에 `previewImage`를 신규 추가하지 않고 기존 `image` 필드를 그대로 사용하여 구현 복잡도를 줄임.
